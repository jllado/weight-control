# Weight Control lessons

Read relevant entries before planning, implementation, and review. Each lesson includes the context needed to apply it; current user requirements and repository contracts take precedence. Update superseded guidance after a correction is verified.

- **Separate app archive paging from private Coach reflection overviews:** The app and two private DAILY Coach endpoints used the same unpaged `getOverview(User)` result. Changing that method to a page broke the Coach controller and would truncate its reflection catalog. Keep the Coach DTO and method unpaged; add an app-only paged DTO and owner-scoped, newest-first ten-row query for `/api/reflections?page=N`. Verify more than ten saved rows through both private Coach routes, the app's first and later pages, Home's first/latest read, and mobile and desktop archive navigation. PrimeVue's responsive paginator uses inclusive max/min widths, so check the exact breakpoint for duplicate controls.
- **Build Madrid time fixtures with the date's actual offset:** Relative `OffsetDateTime.minusHours` retains a fixed offset across the autumn clock change, while stored meal dates and times are later interpreted in Europe/Madrid; hard-coded `+02:00` browser reminders also display the wrong local hour after the switch. Use zone-aware elapsed-time arithmetic for relative fasting meals and derive the offset from the reminder date. Verify focused fasting and reminder tests on a clock-change day, then rerun the full backend and browser gates; do not change production time semantics to satisfy an inaccurate fixture.
- **Poll responsive dialog geometry after resizing:** An immediate viewport-bound assertion intermittently sampled a routine editor while its responsive layout was settling under the full parallel browser gate, despite passing focused runs. Keep the same viewport and internal-overflow predicates, but use a bounded Playwright retry after each resize before taking screenshots. Verify repeated focused parallel runs and the complete browser gate; a transient first sample does not establish a product overflow.

- **Match dashboard navigation controls to neighboring panels:** The Actions panel used a plain Manage link where the dashboard uses outlined PrimeVue buttons. Reuse the existing labeled navigation-button pattern and preserve selected-date route queries; verify keyboard navigation and mobile/desktop alignment without changing surrounding dashboard controls.

- **Render weekly recommendations once across every surface:** Weekly reports repeated advice in domain next actions and the next-week list, and app/email rendering could drift. Use one semantic mapper for app, HTML and plain text: next-week actions first, then domains in fixed order; trim and case-fold exact duplicates while retaining first wording and all provenance. Keep domain summaries without rendering their actions again. Resolve activation through owned stable source identity and normalized original text rather than position, and keep activation state outside saved evidence. Verify one recommendation occurrence in app and both email parts, source reordering/replacement, record subjects/units, and legacy snapshots with missing optional nutrition before release.

- **Classify clear fruit when Coach creates or changes a meal item:** A saved fruit food can carry `fruit=false`; copying that catalog flag into a new snack leaves the fruit routine incomplete even though the item is clearly fruit. Send `fruit=true` explicitly for new or changed clear-fruit items, including reused catalog foods; omit the flag for an unchanged existing meal item so its classification is inherited. Use false for nonfruit or genuinely uncertain items, and do not rewrite historical food, meal, or routine records. Verify the exact proposed Action arguments in a fresh published read-only catalog-reuse conversation and the effective model; separately verify a confirmed Coach save persists the flag and reconciles routine evidence after refresh, with edit/delete removing only automatic evidence and preserving manual check-ins. Read back the published instruction and schema hashes because a visible editor value alone does not establish publication.
- **Keep scoped evidence rules scoped when compacting GPT instructions:** Fitting a new rule under the 8,000-character ceiling turned nutrition's unfinished-day adequacy rule and training's sparse-evidence inference rule into a global unknown-data rule, incorrectly hiding observed current-day values and recorded zero. Keep missing/null values unknown globally, preserve observed values, and scope adequacy to completed days with full coverage and uncertain training conclusions to sparse evidence. Review every shortened clause against its original scope, then check the exact source budget and fresh published behavior separately; source validation alone does not establish publication or acceptance.
- **Match Coach Action enum labels to backend JSON:** A workout Action schema listed `SPEED` for `cardioMetric`, while the Java enum serializes `SPEED_KPH`. When adding an editable record schema, compare every enum value in both new and reused schemas with the backend enum or a serialized response. Verify a focused response containing the value and run `scripts/check.sh frontend check:coach`; YAML validation alone cannot detect a valid but inaccurate enum label.
- **Bound Coach exercise lookups apart from large plans:** `getActivePlan(WORKOUT)` can return a large weekly plan and the entire exercise catalog, too much for a GPT to load when it needs one completed-log exercise ID. Use an optional specific name query on the same Action to return only matching exercises without the plan, cap the result and require refinement for broad matches; keep the unfiltered plan-edit response compatible. Verify the filtered response shape, result bound, authorization and unchanged plan-edit read with focused backend/schema checks, then use a fresh read-only published Action probe.
- **Use absolute workout end times in Coach writes:** Workout `startTime` is local `HH:mm`, but `endTime` maps to Java `Instant`; a clock-only value such as `13:11` is invalid. Send a complete ISO-8601 date-time with `Z` or an offset, or omit `endTime` when only local time is known. Never infer an instant from duration, and preserve the saved full value on edit. Verify typed Action guidance and the proposed JSON in a fresh read-only published GPT probe before any confirmed write.
