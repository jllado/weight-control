# Weight Control lessons

Read relevant entries before planning, implementation, and review. Each lesson includes the context needed to apply it; current user requirements and repository contracts take precedence. Update superseded guidance after a correction is verified.

- **Distinguish GPT model family from Pro power when testing Actions:** A confirmed dinner's identical `createMeal` payload ended without approval or a result under both `gpt-6-pro` and `gpt-5-6-pro`; GPT-5.6 Medium (`gpt-5-6-thinking`) produced approval and saved it. Switching model families can retain Pro power. Verify the actual model and approval metadata, compare pending arguments, check for existing records before retrying, and independently read back every confirmed field. A successful read-only Action does not establish consequential-write behavior; the selected Thinking mode is a verified workaround, not a platform repair.
- **Check failure scope before changing host networking:** A private GPT meal-save failure was reported on both desktop and phone after desktop Chrome showed `ERR_NETWORK_CHANGED`. Local Docker interface churn cannot by itself establish the cross-device cause. The phone was subsequently identified as showing the same conversation. Ask whether another device made an independent attempt or reopened the same stalled conversation; compare model, generated Action, approval and server-result evidence separately. Treat a successful retry as recovery until the original failure is reproduced and the proposed fix is isolated.
- **Inspect the signed-in browser and pending Action approval before diagnosing a stalled GPT save:** A fresh browser profile incorrectly suggested missing authentication, while the user's existing Chrome session was signed in. During the real retry, `ERR_NETWORK_CHANGED` hid the pending `createMeal` approval; reloading recovered Allow once and the server saved successfully. Connect to the existing session, inspect request/status evidence, check persisted records before retrying, and preserve the confirmed payload. Verify one matching saved record and a completed GPT reply; concurrent Docker interface churn is a correlation until isolated, and a successful model switch alone does not prove a model defect.
- **Distinguish buffered workflows from compact record actions:** The button source contract rejected the approved labeled guided Edit control, which opens a current-set buffer with Apply/Cancel. Keep compact record actions icon-only, but document exact approved descriptive-workflow exceptions rather than changing their visible labels to satisfy a broad icon rule. Verify the source contract and the workflow's existing dialog behavior before release.
- **Preserve recorded workout durations:** Planned targets use five-second steps, but recorded durations accept exact whole seconds. Include an existing non-five-second remainder in recorded/editable Seconds choices so imported values remain visible; keep planned choices in five-second steps. Preserve pre-existing drafts and verify copy/edit plus Review → save → reload at multiple exact recorded values, independently from valid planned targets.
- **Initialize source-read identity before reactive form replacement:** Vue 3.2 date watchers can run synchronously during `created`, so replacing a new-workout form before setting its source-read date started duplicate preload requests and retired the pending read. Set the intended date identity before replacement; retire independent source reads on cancel/reopen and destination-date changes. Verify one initial read, held-response cancellation, out-of-order dates, independent failures and retry without losing the other source or edited fields; hold both optional reads and scope simultaneous loading assertions by source.
- **Coordinate nested PrimeVue popup lifetimes:** In PrimeVue 3.38.1 a Dropdown defers hiding after Escape while Dialog's document listener closes its modal, and an older popup may hide after another opens. Track each popup through installed lifecycle events and disable modal Escape while any popup remains open; retain library keyboard handlers. Verify popup Escape preserves the confirmation, closed-control Escape cancels with trigger focus, and source switching survives deferred hide.
- **Stage DOM actions with visible forms:** A new-workout confirmation hid the editor while the original `addLine` still scrolled to its missing element. Insert the scratch line and schedule its scroll after Continue makes the editor visible; source-only Cancel must avoid editor DOM work. Verify Cancel and Continue with render/page-error capture, including source selection and timer start.
- **Exercise every guided-workout transition:** Distinguish a recorded skip from advancing without logging; check exercise timers, pause/resume, supersets, Review, and persistence together. Expose imported helpers through Options API component methods before using them in templates.
- **Run Playwright against the source worktree's build:** The default Playwright config reuses an existing server, so a successful local build can be followed by browser tests against another checkout's stale assets. In isolated worktrees set `WEIGHT_CONTROL_E2E_PORT` to a dedicated port, confirm the server serves the candidate's `dist/`, and verify its startup in the test log or independently compare a served asset with the candidate before attributing results to the current source.
- **Keep exercise metadata consistent:** Carry exercise types, units, and muscle selections through the catalog, plan editor, guided session, saved workout, and Coach. Preserve primary/secondary muscle assignments and fractional equivalent-set accounting; verify the same assignments and totals across editing, saved workouts, and training-balance views.
- **Make invalid inputs discoverable:** Show the actionable validation message and scroll to the first invalid field; check long labels and actual controls at narrow mobile widths.
- **Separate weekly measurement windows:** Label Saturday–Friday averages separately from dated Friday–Sunday outcomes. Keep archive rows concise, put detail behind navigation/disclosures, and refresh the selected detail along with the list. Preserve the saved snapshot rather than silently recomputing historical values.
- **Keep sleep goals and trends distinct:** Show measured values with negative integer-minute deficits only below a goal; omit zero/positive goal deltas and individual goal-status labels. Keep combined-summary wording and independent trend comparisons; omit value–delta dots. Check values below, at, and above each goal in dashboard and history views.
- **Keep nutrition summaries concise:** Show 30-day nutrient trends below the longest fasting period using its label/value columns, typography and spacing; omit the date-window heading and covered-day counts. Put plots in Charts → Nutrition; preserve recorded values while omitting target comparisons, seven-day rows, and chart data disclosures. Verify summary alignment, spacing and overflow against the fasting row, plus accessible plots at mobile and desktop widths.
- **Align dashboard grid rows to their shared columns:** Week Score is one continuous PrimeFlex grid, so each row must reserve the leading spacer and label columns before its seven dates and total. Keep action labels in the label column; stack a compact icon action when the narrow label column cannot fit both controls side by side. Give every cell in a highlighted row the same background. Verify cell coordinates against a neighboring row, no page overflow, accessible activation, and screenshots at 376, 390 and 1280px.
- **Load shared data in every consuming tab:** Meal scores appeared in Nutrition but were absent from Status, whose refresh also skipped meal loading. Reuse the same data-loading path in every consuming tab; distinguish pending, failed, empty and unrated reads while preserving each record's name and date. Verify default-tab loading, failed-read refresh, external changes after reload, selected-date isolation and mobile layouts.
- **Separate trend direction from target status:** A 30-day calorie average can be falling yet remain above target, or rising while within target. Compare the current average with the mean effective target for exactly the recorded dates in its window, using dated plans before weekday defaults; keep the previous-window change labeled separately. If any required target is unavailable, leave the status neutral. Verify every target-color boundary, mixed/partial date coverage, historical selection, missing history, and responsive visible text.
- **Verify Coach persistence and publication:** A reflection is complete only when the full accepted payload, including relevant meal/workout summaries and next action, is saved within DTO limits and read back. Changes to GPT instructions or Actions require the documented publication and published-configuration checks.
- **Test the stable boundary in Coach prompts:** A generic “stable means no follow-up” rule still allowed the model to ask about perceived effort or volunteer hypothetical qualitative gains for identical workout numbers. Separate actual increases from stable or lower measurements, make stable responses numeric-only when no subjective review was requested, and verify the final published wording in a fresh conversation.
- **Retain dates when bounding Coach context:** Reduce response size without dropping requested time windows or evidence needed by the reflection. Distinguish missing observations from zero values; never invent measurements from unclear screenshots.
- **Respect completed records and weekly plans:** Use the completed day's intake as authoritative. Evaluate training against the weekly plan, including recovery days, rather than demanding strength work every day.
- **Serialize reminder requests explicitly:** Send the request DTO fields, excluding response-only fields such as timeZone. Exercise schedule save with date/time changes and restore original settings after production acceptance.
- **Preserve meal details and default scope:** Coach meal writes require a food breakdown and default omitted duration to 30 minutes; the historical verification covered source changes only, without production deployment or GPT publication. Verify the published behavior before treating this requirement as delivered. The manual New meal form defaults regular meals to 30 minutes and snacks to five, preserving custom/cleared values and existing/copied durations.
- **Bound day-based adherence:** Per-routine percentages must not exceed 100%. Check individual charts and aggregate summaries together; use distinct eligible days where the metric counts days, with matching numerator/denominator windows.
- **Keep routine identity separate from automation state:** Each already assigned routine owns one fixed completion rule; offer a checkbox rather than arbitrary rule selection. Migrate existing enabled assignments without recreating routines or history. Pausing must retain automatic check-ins, evidence and streak totals during source edits/deletions; verify disable/save/reload/enable, manual completion/undo and reconciliation for all six rules.
- **Associate PrimeVue InputNumber labels with `inputId`:** `id` can land on the component wrapper instead of the native spinbutton, leaving a visible label disconnected. Set the InputNumber `inputId` to the label's `for` value and verify the control through the browser's accessible name at desktop and mobile widths.
- **Align timer persistence checks with the saved clock semantics:** A restored countdown changes while navigation and dialogs run, so subtract elapsed clock time between reads. Workout phase totals include rest, while per-exercise durations exclude rest; derive saved minute assertions from the persisted phase timer and verify exercise duration separately.
- **Scope migration-count tests to the migration under test:** Later schema migrations change Flyway's pending count through `latest`; target the exact migration version and let full application startup validate newer migrations.
- **Seed Instant boundary fixtures in UTC:** Hibernate stores `Instant` values with `hibernate.jdbc.time_zone=UTC`, while a raw JDBC `Timestamp` used the JVM's Europe/Madrid zone and shifted a midnight fixture by two hours. Seed UTC `LocalDateTime` values when using raw SQL and assert the repository's loaded `Instant` before testing inclusive/exclusive date boundaries; include the selected date's Madrid midnight and the next midnight.
- **Normalize legacy snapshot semantics only when comparing:** Old immutable workout targets can omit `stretchingUnit`, while plan-target deserialization defaults it to SECONDS. Canonical matching must apply that same semantic default without rewriting the recording; deserialize both real converters in regression coverage, assert equal identity, and retain the original null snapshot. Keep explicit BREATHS distinct.
- **Require whole-day evidence for whole-day plan judgments:** With editable weekly plans and no version history, a plan created, edited or archived during the selected date cannot establish its earlier missing-session expectations. Optional user-entered clocks and logging timestamps cannot reconstruct that intention. Require a known version at Europe/Madrid midnight covering the date, label partial-day evidence ambiguous, and verify same-day events plus exact midnight boundaries.
- **Use historical migration timestamps:** When a migration must preserve row metadata, seed historical timestamps, preserve ON UPDATE columns explicitly, and compare pre/post snapshots; same-second inserts can hide unintended timestamp changes.
- **Complete authorized signup email confirmation before requesting manual help:** A branded-account signup was repeatedly handed back for an email code despite a connected mailbox and explicit authorization to finish it. When the applicable workflow permits it, retrieve the specific signup confirmation from the authorized mailbox and enter it through the normal interface without logging the code. Ask for direct participation when an actual human-verification or identity check blocks progress. Verify the resulting account state; accepted email confirmation does not establish an active profile or advertising access.
- **Verify form persistence and notification delivery separately:** A recruitment form’s Preview checks were mistaken for submitted applications while self email alerts were disabled. Use an isolated duplicate for an authorized real submission; confirm its saved record, the recipient’s received mailbox labels and delivery headers, and the live form’s saved notification settings after reload. Update the privacy disclosure before enabling answer copies, then remove the synthetic record and close the duplicate.
- **Mount protected routed consumers once after authentication:** A guided page could mount during delayed authentication without its global coordinator provider; reparenting ordinary routes from an unauthenticated fallback into that coordinator also remounted them, duplicated initial reads and lost the first diary error. Limit the unauthenticated fallback to the public Login route and keep protected views within their authenticated provider. Verify delayed-auth direct guided loading/reload, zero ordinary protected reads before authentication, exactly one initial read afterward, retained tab drafts and visible error → Retry → empty state. Capture Vue console and page errors; compare unchanged tests against released and prior source when attributing a regression.
- **Retire asynchronous guided operations with their lifecycle:** Delayed record reads or editor-lock acquisition must not reopen a session after navigation or logout; coalesce repeated acquisition for the same owner and cancel obsolete operations before applying results. Successful Save must remove only its captured account and recording key, retaining Login or a newly selected draft. Capture coordinator ownership in scoped route guards rather than relying on an Options API instance that authentication teardown may remove before a queued guard runs; verify held reads, held native locks, duplicate Resume, pending Discard, and held Save through navigation and account changes.
- **Keep guided workout essentials visible:** Use read-only current and actual-next summaries with pictures, full names, instructions and targets; keep active Set elapsed separate from accumulated Exercise time and immutable planned duration or rough estimates. Use buffered Edit with Apply/Cancel and a focused Rest dialog that keeps active rest running on dismissal. Place Keep screen on directly below the title, and expose distinct Minimize/Close consequences through tooltips and accessible descriptions. Verify exact recorded seconds through Save/reload, dialog focus return, navigation ownership, long labels and page overflow at mobile, desktop and adjacent responsive breakpoints, including the shared header.
- **Capture weekly comparisons in immutable snapshots:** Compute matched Saturday–Friday baselines when the summary is created: prior week shifted by seven days and year-ago week shifted by 364 days. Store baseline counts and check-in coverage with the snapshot instead of rebuilding comparisons from mutable health history when sending mail. Any baseline check-in makes a zero-episode period observed; no check-ins and legacy snapshots without baseline fields remain unknown. Verify exact inclusive windows, independent baselines, legacy JSON reads and that saved summaries remain unchanged.
- **Preserve personal-record subjects in weekly snapshots:** Weekly summary emails are reconstructed from immutable snapshots, so storing only a metric label, value, unit and date loses the exercise or behavior subject that distinguishes otherwise repeated records. Capture the subject label whenever the subject type differs from its metric domain, then apply the same suffix when rendering saved emails. Keep old snapshots with no subject label readable and unchanged. Verify exercise and behavior subjects, a domain-level row without an added subject, and legacy JSON without the optional field.
- **Keep weekly summary reminders aligned with the latest unsaved Friday:** A new due week must retire pending reminders for older Fridays while retaining their deduplication records; a reminder check must also run after a scheduled email failure because the email schedule is independent. Verify that advancing a week leaves only the latest reminder pending and that an email exception does not skip the reminder check; a saved current week must leave no matching reminder.
- **Choose a manual workout source before opening its editor:** The New workout confirmation is the source choice point; repeating Previous workout and Planned workout selectors inside the editor duplicates a completed decision. Keep both selectors and their independent load/error/empty states in the confirmation, copy the selected source on Continue, and leave the post-Continue editor focused on editing. Verify scratch and preselected previous/planned copies, preserved destination date, cancellation, source-free editor controls, and unchanged edit/plan/timer-resume entry paths.
- **Apply sleep minimums in every interpretation:** Saved sleep feedback compared 6h34 asleep with a seven-hour target even though the personal total-sleep minimum was six hours; composite scores also retained a nine-hour in-bed cap. Put the numeric RECOVERY minimums (25,200 seconds in bed, 21,600 seconds asleep) in the GPT rule itself: a fresh post-save conversation cannot look up RECOVERY first, and field names alone may leave its thresholds unresolved. Use submitted seconds for immediate confirmed-save feedback and dated RECOVERY for later reads, commentary, reflections and duration warnings; compare raw seconds inclusively and keep efficiency/midpoint independent. Preserve measurements and historical reflections, and reassess only affected active warnings through the existing dated/versioned resolve flow. Verify the 6h34/7h35 example, exact and one-second-below thresholds, more than nine hours in bed, missing evidence, frontend/backend parity and fresh published Coach conversations.

- **Align persistent defaults across profile representations:** A new personal percentage preference defaulted to 17 in SQL and Java but to null in the frontend model, so an omitted-field profile showed an incorrect zero-length interval. Apply the agreed default in the migration, entity and client model; keep request omission distinct from reset so older writes preserve the saved preference. Verify omitted-field Home/form reads, custom values, cold reload, owner isolation and unchanged measurements.
- **Scope PrimeVue time-step actions to their calendar:** When a form contains independent delivery and reminder calendars, both overlays can expose identical “Next Minute” buttons, making page-global Playwright locators ambiguous. After opening a time input, scope actions through its `aria-controls` panel. Verify each schedule's separate day/time draft and rerun the settings browser suite and full browser gate.
